# refit2026 — validating the repair for the 2026 model decay

Built 2026-08-20 after the operator reported the model "doing terrible lately".
The diagnosis is in `CHANGELOG.md` and the `2026-08-20_model_decay_diagnosis`
memory. This directory holds the validation, not a shipped change — **nothing
here writes to `data/`, the ledger, or any model artifact.**

Run order, because each script exists to check the previous one's confound:

| script | question | answer |
|---|---|---|
| `harness.py` | Which candidate repair beats shipped on AUC in all three splits? | Only `l2_10x`. Dropping either half of the collinear slg/iso pair moves AUC ≤0.002; re-shrinking the park factor moves it ≤0.0002. |
| `l2_sweep.py` | Is L2=0.5 a lucky grid cell? | No — smooth bias/variance curve, but the raw-scale gate fires **zero** bets at L2≥0.5. That turned out to be an artifact of gating pre-calibration. |
| `money.py` | Same, with the shipped CIR calibrator in the loop. | Gate fires again. L2=0.5 on 2026: 109 bets @ 71.6%, +33.8% ROI vs shipped 150 @ 63.3%, +18.4%. Looks fantastic — which is why the next script exists. |
| `baserate_control.py` | Is that skill, or the train/test base-rate gap? | **Mostly the gap.** An oracle level correction on the *shipped* model alone swings ROI from −12.0% to +2.9% (2025→2024) and +3.7% to −6.0% (2024→2025). L2 does survive the control (+6.7/+1.5/+9.9 pp) but is a minor term next to level. |
| `recal_walkforward.py` | Then just track the level — refit the calibrator more often? | Logloss better in **18 of 18** window/cadence settings; level bias +0.0243 → +0.008…+0.019; flat ROI better in 18 of 18. But the day-level bootstrap CI spans zero (+4.58pp, [−3.95, +12.99], P=82%). |

## Things that will bite you here

- **Park factors are rebuilt inside every split from training seasons only.**
  Never read `data/fi_park_factors.json` in a validation — that file was built
  from `picks_2026.csv` and scores +0.690 in-sample against −0.057 out.

- **`_ptfix`, not `_pit`.** See the `2026-08-02_training_data_leakage` memory.

- **The 2024/2025 backtests were generated by the legacy pipeline**, so
  `lambda_total` and `yrfi_prob` correlate 0.997 there. Any legacy-vs-shipped
  comparison on those files returns a meaningless tie unless you first
  re-score them through `lr_t1.json`/`lr_b1.json`.

- **A gate is a cut point on a level.** Every money number in `money.py` is
  dominated by where the train/test base-rate gap pushed the level, not by
  discrimination. Always run `baserate_control.py` before believing an ROI.

- **Pooled AUC across calibrator vintages is not meaningful.** A calibrator is
  monotone and cannot change ranking, but the ledger's `nrfi_prob` was written
  by several vintages (CIR swap 2026-07-28). After the swap
  spearman(raw, shipped) = 1.0000 and the AUCs agree exactly; before it,
  spearman is 0.9649. The same applies to the walk-forward series, which
  refits on a cadence — do not credit it with a ranking gain.

- **The simulated gate is not the real bet set.** These scripts apply only
  `p_nrfi < 0.42`. Production also applies the lambda floor, thin-pitcher
  demotion, cluster demotions and the daily cap, so counts here (326 season
  2026) differ from the ledger's 391 STRONG bets.

## The finding that matters most

The shipped model's AUC on 2026 is ~0.51 and its 2026 in-sample (0.5208) and
out-of-sample (0.5241) figures are the *same*, so this is not overfitting — it
is a relationship that held in 2024–25 and stopped holding. Every repair here
is therefore a repair to the LEVEL. None of them creates discrimination, and
no intercept can.
